# Конфигурация PostgreSQL и миграции

Основное приложение и TypeORM CLI используют src/database/database.config.ts.
Реквизиты задаются через DB_HOST, DB_PORT, DB_USERNAME, DB_PASSWORD и DB_DATABASE.
Список переменных есть в .env.example. Существующий .env не перезаписывайте.
Для приложения рекомендуется отдельная роль PostgreSQL с минимальными правами;
создание роли и замена ранее опубликованного пароля выполняются отдельно.
CLI использует встроенный loadEnvFile (Node.js 20.12+; рекомендуется Node.js 22+).

synchronize и migrationsRun выключены во всех окружениях. Запуск бота не
изменяет схему и не применяет миграции.

## Новая пустая база

1. Создайте базу и задайте реквизиты в окружении.
2. Выполните npm run migration:run.
3. Запустите приложение.

Начальная миграция создаёт четыре таблицы сущностей и две таблицы связей,
включая ограничения уникальности, индексы и внешние ключи.

## Существующая база, ранее созданная через synchronize

Не выполняйте начальную миграцию обычным способом: таблицы уже существуют.
Сначала сделайте резервную копию и выполните:

~~~bash
npm run schema:check
npm run migration:show
~~~

schema:check только сравнивает схему с сущностями, SQL изменений не выполняется.
Продолжать можно, только если схема совпадает и единственная ожидающая миграция —
InitialSchema1789516800000. Если миграций больше или есть различия, сначала
разберите их: --fake отмечает все ожидающие миграции, а не только начальную.

Для совпадающей существующей схемы зарегистрируйте начальную миграцию без DDL:

~~~bash
npm run migration:run -- --fake
~~~

Эта команда изменяет таблицу истории миграций. Она не выполнялась автоматически.
Откат начальной миграции удаляет таблицы с данными: не используйте migration:revert
для отмены одной лишь регистрации существующей схемы.

## Последующие изменения

~~~bash
npm run migration:generate -- src/database/migrations/DescribeChange
npm run migration:show
npm run migration:run
~~~

Перед применением просмотрите сгенерированный SQL. Проверяйте миграции на отдельной
тестовой базе. Генерация сравнивает сущности с базой из текущего окружения.

## Сервер

~~~bash
npm run build
npm run migration:run:prod
npm run start:prod
~~~

Миграции выполняются один раз отдельным шагом развёртывания, а не каждым экземпляром
приложения. При необходимости используйте отдельные реквизиты с правами DDL для
шага миграций и ограниченные права для работающего бота.
